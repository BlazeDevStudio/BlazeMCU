# ESP8266 reference boards (PREVIEW / unverified)

This is the second supported **build target**, separate from the ESP32 ESP-IDF project. Initial reference boards are NodeMCU 1.0 with ESP-12E and Wemos/Lolin D1 mini with ESP-12F-type module (vendor variants need acceptance testing). Compiled firmware does not prove physical electrical compatibility.

## Build

Install Python 3 and PlatformIO Core 6.1.18. From the BlazeMCU repository root, run:

    pio run -d esp8266 -e nodemcuv2
    pio run -d esp8266 -e d1_mini

The source is esp8266/src/main.cpp. ESP8266 PIN capabilities are in esp8266/include/blaze_caps.h. The web HTML is shared with ESP32 at main/web/index.html and is embedded automatically as ROM-backed PROGMEM at build time. Do not edit the generated header. No extra filesystem upload is required. Board images are in esp8266/.pio/build/{nodemcuv2,d1_mini}/firmware.bin. They are not compatible with ESP32 and should not be used with its partition table. The 4 MB reference boards are not a claim about every ESP-12 module's actual flash size.

## First boot

Serial at 115200 baud. Device starts the radio in station mode solely to acquire hardware entropy for first-run credentials via ESP.random(), then switches to a password-protected offline SoftAP. A random AP password and admin token are persisted in ESP8266 EEPROM-emulated flash. GPIO lab assignments, pin state, reactions and counters are never persisted. Credentials are printed to UART at each boot, so protect provisioning logs and do not use this preview as a finished commercial configuration. Portal: 192.168.4.1. SSID suffix is four hexadecimal chip-ID characters; this suffix alone is not guaranteed globally unique.

## Pins and nonpersistent test limits

Every documented digital number 0–16 and A0 is visible. ESP8266 GPIO6–11 are flash-connected or flash-dependent and all digital operations are hard-denied even after acknowledging warnings. GPIO0/2/15 are boot straps and require an explicit acknowledgment for digitally supported operations. GPIO1/3 use UART0 and require acknowledgment. GPIO16 supports steady input/output but not this application's PWM or interrupt capture; pull-up is rejected. A0 is labeled ADC only, not fictional GPIO17. It is selectable for educational reference but not digitally driven or sampled by this firmware. Board-specific external ADC dividers may scale A0 differently; never assume 3.3 V is safe on the raw chip TOUT pin.

The active lab can exercise a **single pin at a time** for up to 20 seconds. Edge counts are polled, so fast edges can be missed. STOP switches the tested pin back to input/high impedance, not necessarily a safe external electrical state. No PWM, reaction mappings, display driver or UART monitor exists yet. GPIO state is RAM-only. Check the actual PCB schematic and external wiring.

## Firmware loader and recovery

PREBOOT and FLASH are HTTP 501/disabled in this build. ESP8266 Arduino-core OTA uses eboot to copy a staged sketch over the old sketch during reset; that is not a proven nonpersistent one-shot boot. Do not claim a factory slot can always be recovered.

Use ESP8266 ROM serial download mode for authorized recovery. Usually hold GPIO0 LOW when resetting, keep GPIO2 HIGH and GPIO15 LOW, then flash a correctly located complete image with esptool through a 3.3 V adapter/USB serial. Save board-specific flash parameters and credential provisioning records beforehand. Never use ESP32 partition offsets here. Power-loss, serial recovery, wrong-image rejection, GPIO idle and startup credentials need real-board validation.

## PWM preview

ESP8266 supports bounded software PWM only on registry PWM-capable pins (not GPIO16). A 100–1000 Hz frequency and 0–100% duty range is enforced on the device. PWM is stopped before pin release and expires with the same 20-second session lease; effects on external loads are not physically verified.
